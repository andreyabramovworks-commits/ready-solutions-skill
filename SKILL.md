# Ready Solutions

Search `catalog/*.json` and inspect complete source snapshots under `libraries/` before proposing or adapting a solution. Use `node scripts/search.mjs "форма" --tag layer:react --limit 10` for discovery; `--json` returns structured results and `--role copyable-component` narrows the source role. Use `node scripts/shortlist.mjs "диалог"` to compare a few different sources. Default search shows `selectable` entries and omits link directories, support packages, and library internals; `--include-all` includes them. Every entry has multiple tags from distinct facets. Domain tags are general; `rtm_area` is optional context, never a dependency. The `entry_role` field separates component source, examples, public APIs, support packages, link directories, and library internals. Catalog entries generated from filenames are navigation hints, not a review of each implementation: inspect the actual source, package metadata, and examples before recommending it. Entries with `purpose`, `use_when`, and `check` have focused manual notes. `evidence` records code, styles, tests, exports, and imports inspected from the local snapshot. Run `node scripts/validate.mjs`, `node scripts/audit.mjs`, and `node scripts/smoke-search.mjs` after catalog edits; audit flags are in `reports/catalog-audit.json`.

For a new project, inspect its stack and constraints, then verify compatibility against the locally stored source and current upstream documentation when available. Compare a small set of relevant options, explain tradeoffs, and ask which to adopt when the user wants a choice. Do not copy code into a project without inspecting its license and required dependencies. Keep original notices.

Every selectable catalog record has an individual JSON card in `cards/<source>/<solution-id>.json`. Read the card for purpose, local source path, tags, dependencies, adaptation notes, and the verification method. `verification.behavior_tested` distinguishes source inspection from runtime testing; do not imply a component was executed when this is false. The catalog contains complete source snapshots without Git history, not installed runtime dependencies. Never execute repository scripts merely to inspect a candidate. `application_guide` is generated from source role and is a starting instruction, not a completed component review. `evidence.workspace_alias_imports` names project-local helpers and aliases, not installable packages; adapt them when copying code. Directory catalogs provide links and descriptions, not bundled code for every project they list. See `references/taxonomy.md` for tag meanings, `references/source-guide.md` for source boundaries and choice rules, and `catalog/` for precise source commits.

To visually inspect a solution, open `gallery/index.html` locally, search its name, and select the card. `demo.preview_kind` distinguishes `exact-example`, `component-page`, `source-doc-route` (route found in downloaded source but not live-checked), and `none`. A documentation page may demonstrate the component generally rather than the exact local example. A card without `demo.live_url` has no confirmed runnable demonstration yet. Do not substitute a generic mockup or claim that opening source code executes the component. The gallery works from `file://`; its per-card code is stored in `gallery/code/`. Rebuild its links and code with `node scripts/build-real-gallery.mjs` when sources change; `--offline` refreshes local code without rechecking websites.
